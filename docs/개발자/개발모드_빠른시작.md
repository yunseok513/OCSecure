## 0. 이 문서는 무엇인가

개발자가 **시험 인스턴스에서** 증표 키 없이 암복호화를 바로 해 볼 수 있게 하는 방법입니다. 운영의 통제(증표, 문맥, 자격, 감사)를 그대로 따르면 시험하기가 까다로우므로, 시험 인스턴스에서만 증표 검증을 잠시 끕니다. **운영 인스턴스에서는 절대 쓰지 마십시오.** 켜 둔 채로는 운영 개통 판정(`320_golive_check.sql`)이 「불가」로 나옵니다.

이 문서의 SQL\*Plus와 자바 경로는 소스와 개발자 매뉴얼의 호출 예에 근거해 정리한 것이며, 이 문서를 쓰는 동안 오라클에서 실행해 확인하지는 못했습니다. 처음 해 보실 때 어긋나는 곳이 있으면 알려 주십시오.

**전제.** 설치 매뉴얼에서 마스터 키 주입, 도메인과 키, 증표용 키 등록, 업무 계정 연결(`480`)까지 끝난 시험 인스턴스입니다. 실제 개인정보는 없어야 합니다.

| 하고 싶은 일 | 어디를 보나 |
|---|---|
| 개발 모드를 켜고 끄기 | 제1장, 제5장 |
| SQL\*Plus에서 바로 암호화와 복호화 해 보기 | 제2장 |
| 자바 프로그램에서 해 보기 | 제3장 |
| 데이터 이관(평문을 암호문으로) 연습 | 제4장 |

## 1. 켜기

**접속.** `SYS`, 대상 PDB. 설치 패키지 폴더에서 `sqlplus` 를 시작합니다.

**실행.**

```
@sql/09_test/910_dev_mode_on.sql
```

현재 설정이 나온 뒤 `DEV` 를 입력해야 켜집니다. 켜지면 응용 문맥 모드가 `SIMPLE` 이 됩니다.

**확인.** 「APPCTX_MODE = SIMPLE (개발 모드 켬)」이 나옵니다.

## 2. SQL\*Plus에서 바로 해 보기

**접속.** 업무 계정. 이 계정에 `480_connect_app_schema.sql` 이 실행되어 있어야 합니다.

**실행.** 문맥을 세운 같은 접속(같은 창)에서 호출합니다. 아래 `개발자1` 은 시험용 응용 사용자 이름이며 아무 이름이나 됩니다.

```sql
EXEC OCS_OWNER.PKG_SECURE_API.login('개발자1');
SELECT FN_ENC_NAME('홍길동') FROM DUAL;
SELECT FN_IDX_NAME('홍길동') FROM DUAL;
SELECT FN_MASK_NAME(FN_ENC_NAME('홍길동')) FROM DUAL;
```

암호화(`FN_ENC_`), 색인(`FN_IDX_`), 마스킹(`FN_MASK_`)은 **복호화 자격이 없어도** 됩니다. 문맥을 세우지 않고 부르면 `ORA-20521` 입니다.

**복호화(`FN_DEC_`)는 자격이 따로 필요합니다.** 키 관리자(`OCS_KEYADM`)가 시험용으로 부여합니다. `<업무계정>` 은 이름으로 바꿉니다.

```sql
BEGIN
  OCS_OWNER.PKG_KEY_ADMIN.grant_reveal('NAME', '<업무계정>', 'USER', NULL, '개발 시험');
  COMMIT;
END;
/
```

그 뒤 같은 창에서 `SELECT FN_DEC_NAME(FN_ENC_NAME('홍길동')) FROM DUAL;` 이 평문을 돌려줍니다. 끝나면 `revoke_reveal('NAME', '<업무계정>', 'USER')` 로 거둡니다.

## 3. 자바에서 해 보기

증표 키를 읽는 코드 없이 문맥만 세우는 생성자를 씁니다. **개발·시험 전용입니다.**

```java
OcsSessionSupport session = new OcsSessionSupport(null);   // 증표 없이 문맥만
Connection con = dataSource.getConnection();
try {
    session.establish(con, "개발자1");
    // 이 연결로: INSERT ... VALUES (FN_ENC_NAME(?), FN_IDX_NAME(?)) 등
} finally {
    session.release(con);
    con.close();
}
```

운영으로 옮길 때는 `new OcsSessionSupport(new OcsAppProof(증표키))` 로 바꾸기만 하면 같은 코드가 증표 검증을 거칩니다(개발자 매뉴얼 제4.1절).

설치 매뉴얼 제4.2절의 연동 확인 프로그램(`OcsConnectDemo`)은 운영 방식(증표 제출)을 확인하는 것이라, 개발 모드에서는 항목에 따라 결과가 달라질 수 있습니다. 이 부분은 확인하지 않았습니다.

## 4. 데이터 이관 연습

평문 컬럼을 암호문과 색인 컬럼으로 옮기는 연습입니다. 제3장의 연결 안에서 일정 건수씩 묶어 처리하고 매번 커밋합니다.

```java
PreparedStatement ps = con.prepareStatement(
  "UPDATE 내테이블 SET rrn_enc = FN_ENC_RRN(rrn_plain), rrn_idx = FN_IDX_RRN(rrn_plain) " +
  " WHERE rrn_enc IS NULL AND ROWNUM <= ?");
ps.setInt(1, 5000);
int n;
do { n = ps.executeUpdate(); con.commit(); } while (n > 0);
```

`WHERE rrn_enc IS NULL` 이 처리 완료 지점을 데이터에 남기므로 중간에 멈춰도 다시 실행하면 이어집니다. 컬럼 이름은 현장에 맞게 바꾸십시오. 끝난 뒤에는 건수, 표본 복호화, 색인 검색 결과를 평문 검색과 견주어 검증합니다(설계서 제13장). **시험 데이터는 실제 개인정보가 아닌 값**으로 하십시오.

## 5. 끄기 (반드시)

**접속.** `SYS`, 대상 PDB.

**실행.**

```
@sql/09_test/911_dev_mode_off.sql
```

**확인.** 끝의 조회에서 `APPCTX_MODE` 가 `PROOF` 여야 합니다. 이 설정을 `PROOF` 로 두고 운영 방식으로 다시 확인하려면 설치 매뉴얼 제4.2절을 하십시오. 운영 개통 전에는 `03_grants/320_golive_check.sql` 이 `APPCTX_MODE=PROOF` 인지 다시 점검합니다.

## 6. 하지 말 것

| 하지 말 것 | 이유 |
|---|---|
| 운영 인스턴스에서 켜기 | 접속 정보만으로 암복호화가 되어 이 모듈의 핵심 통제가 사라집니다 |
| 켠 채로 두기 | 운영 개통 판정이 막고, 시험 인스턴스도 그 사이 약해집니다 |
| 실제 개인정보로 시험하기 | 개발 모드의 인스턴스는 통제가 약합니다 |
| 개발 인스턴스에서 만든 암호문을 다른 인스턴스로 옮기기 | 마스터 키가 인스턴스마다 달라 읽히지 않습니다 |

## 7. 근거와 확인 범위

개발 모드가 `SIMPLE` 설정으로 문맥 설정을 증표 없이 허용하는 것, 암호화와 색인과 마스킹이 복호화 자격 없이 되는 것, 복호화에 자격이 필요한 것은 개발자 매뉴얼과 `PKG_SECURE_API` 의 설명에 근거합니다(정확도: 높음, 신뢰도: 높음). 이 문서의 SQL과 자바 예를 실제 오라클에서 실행해 확인하지는 않았습니다(정확도: 중간).

## 8. 결론 요약

시험 인스턴스에서는 `910_dev_mode_on.sql` 로 증표 검증을 끄고 `login('이름')` 한 줄로 SQL\*Plus에서 바로 암복호화를 해 볼 수 있습니다. 끝나면 `911_dev_mode_off.sql` 로 반드시 되돌립니다. 운영 인스턴스에서는 쓰지 않습니다.
