# 문서 지도

문서는 **독자별 폴더**로 나뉘어 있습니다. 자기 폴더의 문서만 읽으면 됩니다.

| 독자 | 폴더 | 읽을 문서 | 하는 일 |
|---|---|---|---|
| 설치 담당자 | `설치/` | `설치_매뉴얼.md` | 오라클에 모듈을 설치하고 확인한다. 윈도우 편과 RHEL 편이 있다 |
| 업무 프로그램 개발자 | `개발자/` | `개발자_매뉴얼.md`, `개발모드_빠른시작.md`, `전자정부_사용설명서.md` | 업무 프로그램에서 암복호화를 호출한다. 시험 인스턴스에서 빠르게 시험한다 |
| 운영담당자, 키 관리자, 감사 담당자 | `유지보수/` | `유지보수_매뉴얼.md`, `오류_대응_매뉴얼.md` | 운영 중의 점검과 변경, 오류가 났을 때의 대응 |
| 이 저장소를 만드는 사람 | `설계/`, `저장소/` | 종합계획, 설계서, 빌드와 시험 설명서 | 설계의 근거와 저장소 작업 방법 |

## 외부에 전달하는 것

기본으로 전달하는 것은 **설치 패키지(`설치_매뉴얼.md` 포함)** 뿐입니다. 개발자와 유지보수 문서는 필요할 때 `python tools/make_install_package.py --with-ops-docs` 로 패키지에 함께 담습니다. `설계/`, `저장소/` 와 저장소 바깥의 `internal/` 은 담기지 않습니다.

## 문서마다 아직 남은 일

문서를 독자별로 정리하는 작업은 단계별로 진행 중입니다. 지금 상태와 앞으로의 계획은 다음과 같습니다.

| 폴더 | 지금 | 계획 |
|---|---|---|
| `설치/` | 한 문서에 공통 장, 윈도우 편, RHEL 편 | 개발·시험 설치와 운영 설치로 나누고 각각 윈도우와 RHEL 편을 둠. 운영 설치편은 외부 키 관리(`EXTERNAL`) 방식이 구현되어 있지 않아 사전 요건과 제한을 먼저 밝히는 형태가 됨 |
| `개발자/` | 세 문서가 따로 있음 | 한 권으로 합침: 빠른 시작, 호출 규격, 문맥, 저장과 검색, 이관, 오류 |
| `유지보수/` | 두 문서가 따로 있음 | 한 권으로 합침: 일상과 정기 점검, 변경 작업, 비상과 오류 대응 |

## 설치 매뉴얼을 고칠 때

`설치/설치_매뉴얼.md` 는 직접 고치지 않습니다. 원본 `설치/설치_매뉴얼.tmpl.md` 를 고치고 `python tools/build_manual.py` 로 다시 만듭니다. 윈도우 편과 RHEL 편의 공통 절차를 한 원본에서 만들어 서로 어긋나지 않게 하려는 방식이며, 점검(`python tools/run_checks.py`)이 결과가 원본과 맞는지 확인합니다.
