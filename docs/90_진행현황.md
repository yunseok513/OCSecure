# 진행 현황

이 파일이 기준입니다. 대화가 길어져 맥락을 놓쳤을 때 여기만 보면 됩니다.
한 단계씩 진행하며, 단계가 끝날 때마다 갱신합니다.

## 작업 방식

작업 환경이 폐쇄망이라 스크립트를 고쳐 다시 반입하는 절차가 무겁습니다.
그래서 문제가 생기면 두 가지를 함께 합니다.

첫째, 저장소의 스크립트를 고칩니다. 다음 반입분과 기록을 위한 것입니다.

둘째, 폐쇄망에서 지금 바로 칠 수 있는 명령을 함께 드립니다. 반입을 기다리지
않고 진행할 수 있어야 하기 때문입니다. 대개는 붙여넣을 수 있는 짧은 SQL 이거나
고칠 한 줄입니다.

반입은 고칠 것이 여러 건 쌓였을 때 한 번에 하는 편이 낫습니다.

최종 갱신: 2026-09-30 (단계 3 완료)

## 지금 할 일

**단계 4. 권한 부여와 자체 시험**

인코딩은 단계 3 에서 맞추었습니다. 같은 방식을 그대로 쓰십시오. 특히 이번
단계의 `901_kat_data.sql` 에는 한글 평문이 값으로 들어 있어, 인코딩이 어긋나면
컴파일 오류가 아니라 시험 실패로 나타납니다.

먼저 권한을 부여합니다. `OCS_OWNER` 로 접속하여 실행합니다.

```
sqlplus OCS_OWNER/<암호>@<호스트>:<포트>/SFISPDB949

SQL> @sql/03_grants/300_grants.sql
```

이 스크립트는 최상위 인터페이스 패키지에만 실행 권한을 주고, 그 아래 계층에는
어떤 계정에도 권한을 주지 않습니다. 정책 계층을 우회한 복호화가 막히는 근거가
전적으로 이 원칙이므로, 스크립트 끝의 점검 조회 결과가 비어 있는지 꼭 보십시오.

이어서 자체 시험을 돌립니다. 같은 계정입니다.

```
SQL> @sql/09_test/900_kat_setup.sql
SQL> @sql/09_test/901_kat_data.sql
SQL> @sql/09_test/902_selftest.sql
```

자체 시험은 설정을 개발 모드로 잠시 바꾸었다가 되돌립니다. 지금은 개통 전이므로
문제가 없으나, 개통 후 운영계에서는 실행하면 안 됩니다.

마지막 줄에 통과와 실패 건수가 찍힙니다. 그 줄과, 실패가 있다면 `[실패]` 로
시작하는 줄을 함께 알려 주십시오. 이 시험이 통과하면 파이썬 참조 구현과 PL/SQL
구현이 바이트 단위로 같은 값을 낸다는 뜻이며, 암호문 포맷이 규격대로 구현되었다는
근거가 됩니다.

## 미결 사항

- 검증필 암호모듈 인증은 별도 과업으로 분리 (docs/30). 이 사업 범위 밖입니다.
- 에디션과 유상 옵션 보유 현황 미확인. 현재 설계는 유상 옵션을 쓰지 않으므로
  당장 막히지는 않습니다.
- TO-BE 문자집합이 MSWIN949 이므로, 기존 비밀번호가 어느 문자집합으로
  해싱되었는지 확인할 때 이 점을 함께 보아야 합니다. 단계 6 에서 다룹니다.
- 오라클 스크립트는 아직 실제 인스턴스에서 돌려 본 적이 없습니다. 단계 2 부터
  하나씩 확인됩니다. 정적 점검기는 컴파일을 대신하지 못하므로, 단계 3 에서
  나온 `SQLERRM` 같은 오류는 실제 컴파일에서만 드러납니다.
- 주민등록번호 기존 키를 찾지 못하면 해당 자료를 되살릴 수 없습니다. 최대 위험.
