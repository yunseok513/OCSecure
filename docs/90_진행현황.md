## 지금 할 일

**단계 1. 오라클 환경 점검**

**대상은 TO-BE 데이터베이스입니다.** 19c 는 멀티테넌트 구조라 컨테이너가 여럿이므로,
설치할 PDB 를 먼저 확인하고 그 안에서 점검합니다. 두 스크립트 모두 읽기 전용입니다.

먼저 어디에 접속했는지 확인합니다.

```
sqlplus / as sysdba
SQL> @sql/01_schema/000_where_am_i.sql
```

PDB 목록이 나오면 작업 대상을 고르고 그 안으로 들어갑니다.

```
SQL> ALTER SESSION SET CONTAINER = <PDB이름>;
SQL> SHOW CON_NAME
```

컨테이너가 바뀐 것을 확인한 뒤 점검합니다.

```
SQL> @sql/01_schema/001_precheck.sql
```

`SYS` 가 아닌 계정으로 돌리려면 그 계정에 `SYS.DBMS_CRYPTO` 실행 권한이 있어야
합니다. 없으면 스크립트가 그 사실과 부여 구문을 알려 줍니다.

확인할 것은 버전과 문자집합, SHA-256 계열과 AES-256 사용 가능 여부입니다.
결과를 알려 주시면 다음 단계를 정하겠습니다.

가지: SHA-256 계열을 쓸 수 없으면 현재 구현을 그대로 설치할 수 없으므로
설계로 되돌아갑니다.

## 미결 사항

- 검증필 암호모듈 인증은 별도 과업으로 분리 (docs/30). 이 사업 범위 밖입니다.
- 오라클 19c 확인됨. 에디션과 유상 옵션 보유 현황은 아직 미확인입니다.
- 인스턴스에 문자집합이 다른 데이터베이스가 둘 있습니다. UTF-8 과 MSWIN949 입니다.
  구현은 항상 UTF-8 로 인코딩하므로 어느 쪽이든 동작하나, 어느 것이 TO-BE 인지
  확정해야 합니다. 기존 비밀번호 체계의 문자집합 설정과도 관련됩니다.
- 주민등록번호 기존 키를 찾지 못하면 해당 자료를 되살릴 수 없습니다. 최대 위험.
