# 진행 현황

이 파일이 기준입니다. 대화가 길어져 맥락을 놓쳤을 때 여기만 보면 됩니다.
한 단계씩 진행하며, 단계가 끝날 때마다 갱신합니다.

## 작업 방식

작업 환경이 폐쇄망이라 스크립트를 고쳐 다시 반입하는 절차가 무겁습니다.
그래서 문제가 생기면 두 가지를 함께 합니다.

첫째, 저장소의 스크립트를 고칩니다. 다음 반입분과 기록을 위한 것입니다.

둘째, 폐쇄망에서 지금 바로 칠 수 있는 명령을 함께 드립니다. 반입을 기다리지
않고 진행할 수 있어야 하기 때문입니다. 대개는 붙여넣을 수 있는 짧은 SQL 이거나
고칠 한 줄입니다.

반입은 고칠 것이 여러 건 쌓였을 때 한 번에 하는 편이 낫습니다.

최종 갱신: 2026-09-30 (단계 1 완료)

## 지금 할 일

**단계 2. 계정과 역할 생성**

TO-BE 는 `SFISPDB949` PDB 로 확정되었습니다. 그 안에 모듈이 쓸 계정 넷과
역할 셋을 만듭니다. SYS 로 해당 PDB 에 접속하여 실행합니다.

먼저 테이블스페이스를 확인합니다. 스크립트가 `USERS` 를 쓰는데 없을 수 있습니다.

```sql
SELECT tablespace_name FROM dba_tablespaces ORDER BY 1;
```

`USERS` 가 없으면 `sql/01_schema/010_users_roles.sql` 안의 `USERS` 세 곳을
쓰실 이름으로 바꾸어 실행하십시오. 나머지는 그대로 둡니다.

```
SQL> ALTER SESSION SET CONTAINER = SFISPDB949;
SQL> @sql/01_schema/010_users_roles.sql
```

계정 비밀번호 넷을 물어봅니다. 계정 이름(OCS_OWNER, OCS_KEYADM, OCS_AUDITOR,
OCS_APP)이 기관 표준과 맞지 않으면 바꾸셔도 되나, 이후 스크립트가 같은 이름을
쓰므로 함께 바꾸어야 합니다.

**이 스크립트는 실제 오라클에서 돌려 본 적이 없습니다.** 오류가 나면 그대로
알려 주십시오. 저장소를 고치고, 폐쇄망에서 바로 칠 수 있는 명령을 함께
드리겠습니다.

## 미결 사항

- 검증필 암호모듈 인증은 별도 과업으로 분리 (docs/30). 이 사업 범위 밖입니다.
- 에디션과 유상 옵션 보유 현황 미확인. 현재 설계는 유상 옵션을 쓰지 않으므로
  당장 막히지는 않습니다.
- TO-BE 문자집합이 MSWIN949 이므로, 기존 비밀번호가 어느 문자집합으로
  해싱되었는지 확인할 때 이 점을 함께 보아야 합니다. 단계 6 에서 다룹니다.
- 오라클 스크립트는 아직 실제 인스턴스에서 돌려 본 적이 없습니다. 단계 2 부터
  하나씩 확인됩니다.
- 주민등록번호 기존 키를 찾지 못하면 해당 자료를 되살릴 수 없습니다. 최대 위험.
