# OCSecure

Oracle Database 테이블 컬럼에 대한 양방향 암복호화 및 일방향 암호화 모듈 개발 프로젝트입니다.

아울러 해당 모듈이 임의로 분석되거나 변조되지 않도록 하는 접근권한 통제 체계의 구축까지를 범위에 포함합니다. 사업은 프로그램 개발 트랙과 보안관리 트랙으로 분리하여 추진하며, 두 트랙을 분리하는 이유는 분량 때문이 아니라 모듈을 만드는 주체와 통제하는 주체가 분리되어야 통제가 성립하기 때문입니다.

`docs/10_암호화모듈_개발설계.md`는 개발 트랙의 설계서입니다. 양방향과 일방향의 분류 기준, 아키텍처 대안 비교와 권고, 검증필 모듈 교체를 전제한 사계층 구조, 암호문 포맷과 알고리즘 선정, 키 관리와 교체 절차, 검색을 위한 색인 설계, 애플리케이션 투명화 전략, 성능 설계, 데이터 전환 절차와 시험 계획을 담고 있습니다.

`docs/50_전자정부프레임워크_사용설명서.md`는 업무 개발자를 위한 사용설명서입니다. 양방향 암복호화와 단방향 암호화의 호출 방법, 그리고 암호화된 컬럼을 검색과 정렬과 조인과 집계에서 다루는 방법을 담고 있습니다.

`docs/70_빌드_및_시험_설명서.md`는 저장소의 파이썬 코드와 자바 코드를 어떻게 준비하고 돌리고 배포하는지를 다룹니다. 환경 준비, 시험 실행, 시험 벡터 재생성, 자바 컴파일과 jar 생성, 설치 패키지 만들기를 담고 있습니다.

`docs/80_설치_매뉴얼.md`는 설치 패키지와 함께 전달하는 설치 매뉴얼입니다. 소개, 설치 전 확인, 설치 진행, 설치 후 확인, 참고 사항의 순서로 작업 흐름을 따라 적었습니다.

`docs/60_비밀번호시스템_관리자설명서.md`는 DB 암호화 시스템 전체의 관리자 매뉴얼입니다. 키 저장소와 도메인과 키 교체, 복호화 자격, 재암호화, 감사와 모니터링, 설정값, 비밀번호 운영, 증상별 조치와 사고 대응, 운영 전환을 표 중심으로 담고 있습니다.

## 구성

`sql/` 아래에 오라클 구현이 있습니다. `00_install.sql` 이 설치 절차서이며, 계정을 바꾸어 가며 번호 순서대로 실행합니다. 운영 중 쓰는 관리 도구는 `04_admin/` 아래에 있습니다. 패키지는 암호 제공자, 암호 연산, 정책, 인터페이스의 네 겹으로 나뉘어 있고, 검증필 암호모듈로의 교체가 최하위 한 겹에서만 일어나도록 경계를 지켰습니다. `08_sample/` 에 투명화 뷰 적용 예시가, `09_test/` 에 자체 시험이 있습니다.

`java/` 에 자바 연동 모듈이 있습니다. 외부 의존성이 없어 전자정부 표준프레임워크 프로젝트에 그대로 넣을 수 있으며, 접속 증표 생성과 세션 문맥 확립, 그리고 데이터베이스를 거치지 않는 연계 자료의 암복호화를 담당합니다. 파이썬 참조 구현과 바이트 단위로 같은 결과를 냅니다.

`tools/refimpl/` 에 파이썬 참조 구현이 있습니다. 암호문 포맷의 실행 가능한 정의이자 고정 시험 벡터의 생성원이며, 자바 등 응용 계층이 같은 데이터를 읽어야 할 때의 대조 기준이 됩니다. `tools/lint_plsql.py` 는 오라클 없이 잡을 수 있는 PL/SQL 오류를 걸러 냅니다.

`tests/` 에 참조 구현 시험과 고정 시험 벡터가 있습니다.

## 점검 실행

```
python tools/run_checks.py
```

리눅스와 맥에서는 `./tools/run_checks.sh`, 윈도우에서는 `tools\run_checks.bat` 도 같은 일을 합니다. 윈도우에는 `python3` 명령이 대개 없으므로 `py -3` 을 쓰십시오.

참조 구현 시험, 시험 벡터의 최신 여부, PL/SQL 정적 점검, 자바 연동 모듈의 컴파일과 벡터 대조를 차례로 수행합니다. 오라클 인스턴스 없이 돌아갑니다.

외부 패키지는 필요하지 않습니다. 파이썬과 자바 모두 표준 라이브러리만으로 돌아가므로, 폐쇄망으로 파일만 옮기면 그대로 쓸 수 있습니다.

배포용 jar 는 다음과 같이 만듭니다. 외부 의존성이 없으므로 빌드 도구 없이 `javac` 만으로도 컴파일됩니다.

```
cd java && mvn -B package
```

실 인스턴스에서의 컴파일과 자체 시험은 이것으로 대신할 수 없으며, 설치 후 `sql/09_test/902_selftest.sql` 을 반드시 돌려야 합니다. 자세한 것은 `docs/70_빌드_및_시험_설명서.md` 를 보십시오.

## 현재 상태

1차 구현을 마쳤습니다. 다만 작업 환경에 오라클 인스턴스를 띄울 수 없어 PL/SQL 의 컴파일과 실행은 확인하지 못하였습니다. 검증한 범위와 검증하지 못한 범위는 `internal/설계결정기록.md` 제2절에 적어 두었습니다.

대상이 관공서 시스템임이 확정되어, 검증필 암호모듈 사용 요건이 적용될 가능성이 높은 것으로 보고 설계하고 있습니다. 다만 검증 획득 자체는 이 사업의 범위에서 제외하고 별도 과업으로 분리하였으며, 이 사업은 검증필 모듈이 확보되었을 때 최하위 한 계층의 교체만으로 전환이 완료되는 구조를 만드는 데까지를 목표로 합니다.

다음 작업은 종합계획 제2절에 정리된 나머지 미확정 사항의 확정이며, 그중 오라클 에디션 및 유상 옵션 보유 현황과 암호화 대상 컬럼의 규모가 우선입니다.
