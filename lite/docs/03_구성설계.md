# 간이판 구성 설계

## 1. 구성 요소

간이판은 오라클 데이터베이스 안의 객체만으로 이루어집니다. 소유 계정 하나가 키 테이블 한 개와 암복호화 패키지를 갖고, 업무 계정에는 짧은 이름의 암복호화 함수에 대한 실행 권한만 부여합니다. 키 테이블에는 업무 계정이 접근하지 못합니다. 상주 프로그램, 서버 파일, 자바 연동 라이브러리는 없습니다. 이 구성은 `01_요구확정.md`의 확정 요구와 `02_설계결정.md`의 키 보관 결정에 근거합니다.

## 2. 기존 전체판에서 가져오는 것

암호문 형식과 암호 연산은 전체판에서 시험을 마친 것이므로 간이판이 같은 형식을 씁니다. 암호문은 버전 1바이트, 알고리즘 1바이트, 키 번호 2바이트, 초기화 벡터 16바이트, AES-256-CBC 암호문, HMAC-SHA256 태그 32바이트로 이루어지며, 태그를 먼저 검증한 뒤에야 복호화합니다. 비밀번호는 PBKDF2-SHA256 해시에 솔트와 반복 횟수를 함께 담은 54바이트 형식입니다. 같은 형식을 쓰면 전체판의 고정 시험 벡터와 파이썬 참조 구현을 간이판 검증에 그대로 쓸 수 있고, 나중에 전체판으로 올릴 때 데이터를 변환하지 않아도 됩니다. 이 형식 설명은 `sql/02_packages/110_pkg_crypto_fmt.sql`과 `150_pkg_crypto_core.sql`의 주석을 읽은 내용에 근거하며 신뢰도는 높음입니다.

## 3. 컬럼 길이

암호문을 16진 문자열(VARCHAR2)로 저장하기로 하였으므로 컬럼 길이가 늘어납니다. 아래 수치는 위 형식의 바이트 구성에서 계산한 값이며 정확도는 높음입니다. 오라클에서 문자 길이 기준 컬럼을 쓰는 경우 16진 문자는 한 글자가 한 바이트이므로 바이트 기준 컬럼도 같은 숫자입니다.

| 대상 | 평문 길이 | 암호문 바이트 | 컬럼 길이(16진) |
|---|---|---|---|
| 주민등록번호(하이픈 없이 13자) | 13바이트 | 68 | 136 |
| 주민등록번호(하이픈 포함 14자) | 14바이트 | 68 | 136 |
| 계좌번호(20자 이내) | 20바이트 | 84 | 168 |
| 계좌번호(32자 이내) | 32바이트 | 100 | 200 |
| 비밀번호 해시 | 해당 없음 | 54 | 108 |

AES의 블록 크기가 16바이트이고 패딩이 항상 붙으므로, 평문 15바이트까지는 암호문 본체가 16바이트, 16바이트부터 31바이트까지는 32바이트가 됩니다. 일반식은 암호문 바이트 수가 4 + 16 + 16 × (평문 바이트 ÷ 16의 몫 + 1) + 32이며 16진 길이는 그 두 배입니다. 한글이 섞이면 UTF-8로 한 글자가 3바이트가 됨에 유의합니다.

## 4. 간이판이 제공할 함수

업무 쿼리에서 부르는 함수는 여섯 개입니다. `FN_SFC_ENC`(식별번호 암호화), `FN_SFC_DEC`(복호화), `FN_SFC_MASK`(마스킹 출력, 유형은 RRN, ACCOUNT, ALL), `FN_SFC_PWD_HASH`(비밀번호 해시 생성), `FN_SFC_PWD_VERIFY`(검증, 일치하면 1), `FN_SFC_READY`(암호화 사용 가능 여부 점검)입니다. 전체판은 주민등록번호, 계좌번호, 성명마다 함수와 키 도메인을 따로 두었으나, 간이판은 도메인 개념을 없애고 모든 식별번호에 같은 함수와 같은 키를 씁니다. 키가 하나이므로 키를 교체할 때도 단계가 하나로 줄어듭니다. 마스킹 유형만 호출 때 지정합니다.

## 5. 확정한 세부 사항

키는 루트 키 하나에서 암호화 키와 인증 키를 유도합니다. 루트 키는 32바이트 난수이며 `SFC_KEY` 테이블에 저장하되, 설치 때 한 번 생성되어 `SFC_SEAL` 패키지에 들어가는 난수(이하 봉인값)로 감싼 형태로만 둡니다. 봉인값 패키지는 패키지 본문을 다시 컴파일해도 바뀌지 않도록 별도 단위로 분리하였고, 두 번째 실행은 스스로 거부합니다. 봉인값을 잃으면 저장된 키를 모두 읽을 수 없으므로 설치 직후 데이터베이스 전체를 백업해야 합니다. 이 방식의 방어 한계는 `02_설계결정.md` 제1절에 적은 대로입니다.

마스킹은 주민등록번호가 앞 여섯 자리와 하이픈만 남기고 뒤 일곱 자리를 가리며(13자리 숫자가 아니면 전부 가림), 계좌번호는 앞 네 자리만 보이게 하고 나머지는 가립니다. 오류는 모두 예외로 던지며 번호는 -20601(인자 오류), -20602(키 없음 또는 봉인값 불일치), -20603(무결성 실패), -20604(암호문 형식 오류), -20605(상태 오류)입니다. 입력이 NULL이면 NULL을 돌려줍니다. 비밀번호 검증에서만 형식이 잘못된 저장값을 오류가 아니라 불일치(0)로 처리합니다.

SQL 파일은 모두 영문 ASCII로 작성하였습니다. 한글이 든 SQL을 CP949 클라이언트로 실행하면 줄바꿈이 사라져 컬럼 정의가 조용히 빠지는 사고가 전체판에서 실제로 두 번 있었기 때문입니다. 한글은 문서에만 둡니다.

## 6. 구현 위치

구현은 `lite/sql/`에 있습니다. 10번이 계정 생성, 20번이 키 테이블, 21번이 봉인값, 22번이 패키지, 23번이 응용이 부르는 여섯 개 함수(`FN_SFC_ENC`, `FN_SFC_DEC`, `FN_SFC_MASK`, `FN_SFC_PWD_HASH`, `FN_SFC_PWD_VERIFY`, `FN_SFC_READY`), 30번이 첫 키 생성, 40번과 41번이 업무 계정 연결과 해제, 50번이 자체 시험, 90번이 제거입니다. 파이썬 참조 구현과 시험은 `lite/tests/`에 있습니다.
