# 간이판 구성 설계

## 1. 구성 요소

간이판은 오라클 데이터베이스 안의 객체만으로 이루어집니다. 소유 계정 하나가 키 테이블 한 개와 암복호화 패키지를 갖고, 업무 계정에는 짧은 이름의 암복호화 함수에 대한 실행 권한만 부여합니다. 키 테이블에는 업무 계정이 접근하지 못합니다. 상주 프로그램, 서버 파일, 자바 연동 라이브러리는 없습니다. 이 구성은 `01_요구확정.md`의 확정 요구와 `02_설계결정.md`의 키 보관 결정에 근거합니다.

## 2. 기존 전체판에서 가져오는 것

암호문 형식과 암호 연산은 전체판에서 시험을 마친 것이므로 간이판이 같은 형식을 씁니다. 암호문은 버전 1바이트, 알고리즘 1바이트, 키 번호 2바이트, 초기화 벡터 16바이트, AES-256-CBC 암호문, HMAC-SHA256 태그 32바이트로 이루어지며, 태그를 먼저 검증한 뒤에야 복호화합니다. 비밀번호는 PBKDF2-SHA256 해시에 솔트와 반복 횟수를 함께 담은 54바이트 형식입니다. 같은 형식을 쓰면 전체판의 고정 시험 벡터와 파이썬 참조 구현을 간이판 검증에 그대로 쓸 수 있고, 나중에 전체판으로 올릴 때 데이터를 변환하지 않아도 됩니다. 이 형식 설명은 `sql/02_packages/110_pkg_crypto_fmt.sql`과 `150_pkg_crypto_core.sql`의 주석을 읽은 내용에 근거하며 신뢰도는 높음입니다.

## 3. 컬럼 길이

암호문을 16진 문자열(VARCHAR2)로 저장하기로 하였으므로 컬럼 길이가 늘어납니다. 아래 수치는 위 형식의 바이트 구성에서 계산한 값이며 정확도는 높음입니다. 오라클에서 문자 길이 기준 컬럼을 쓰는 경우 16진 문자는 한 글자가 한 바이트이므로 바이트 기준 컬럼도 같은 숫자입니다.

| 대상 | 평문 길이 | 암호문 바이트 | 컬럼 길이(16진) |
|---|---|---|---|
| 주민등록번호(하이픈 없이 13자) | 13바이트 | 68 | 136 |
| 주민등록번호(하이픈 포함 14자) | 14바이트 | 68 | 136 |
| 계좌번호(20자 이내) | 20바이트 | 84 | 168 |
| 계좌번호(32자 이내) | 32바이트 | 100 | 200 |
| 비밀번호 해시 | 해당 없음 | 54 | 108 |

AES의 블록 크기가 16바이트이고 패딩이 항상 붙으므로, 평문 15바이트까지는 암호문 본체가 16바이트, 16바이트부터 31바이트까지는 32바이트가 됩니다. 일반식은 암호문 바이트 수가 4 + 16 + 16 × (평문 바이트 ÷ 16의 몫 + 1) + 32이며 16진 길이는 그 두 배입니다. 한글이 섞이면 UTF-8로 한 글자가 3바이트가 됨에 유의합니다.

## 4. 간이판이 제공할 함수

업무 쿼리에서 직접 부르는 함수는 다음 다섯 가지 안팎으로 줄입니다. 식별번호 암호화, 식별번호 복호화, 식별번호 마스킹 출력, 비밀번호 해시 생성, 비밀번호 검증입니다. 전체판은 주민등록번호·계좌번호·성명마다 함수를 따로 두었으나, 간이판은 도메인 코드를 인자로 받는 일반 함수를 기본으로 하고 이름이 다른 도메인 전용 함수는 두지 않겠습니다. 이 점은 아직 확정이 아닌 제안입니다.

## 5. 아직 정하지 않은 것

키 테이블에 저장할 키 구성(루트 키 하나에서 암호화 키와 인증 키를 유도할지, 둘을 따로 둘지), 마스킹 규칙(주민등록번호는 뒤 일곱 자리 가림 등), 오류 처리 방식(예외를 던질지 NULL을 돌려줄지)은 다음 걸음에서 정합니다.
