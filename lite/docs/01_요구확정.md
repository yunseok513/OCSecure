# 간이 암호화 모듈 요구 확정

## 1. 배경과 목적

이 문서는 간이 암호화 모듈(이하 간이판)의 개발 범위를 확정하기 위해 작성합니다. 고객이 현대 시스템에 암호화가 필요하다는 점을 발주 시점에 인식하지 못하여 예산이 확보되지 않은 상태에서, 재정통합시스템 구축팀이 최소한의 암호화 기능을 제공해야 하는 상황이 출발점입니다. 기존 저장소의 `sql/`, `java/`, `docs/`에 있는 구현은 직무 분리와 증표 통제까지 갖춘 전체판이며, 간이판은 이를 수정하지 않고 `lite/` 아래에서 별도로 개발합니다.

## 2. 설계 제약

간이판은 다음 제약을 지켜야 합니다. 첫째, 구성 요소는 오라클 데이터베이스(PL/SQL), 자바, 파이썬 등 현재 프로젝트에서 이미 쓰는 기술에 한정하며, 별도의 저장소나 상주 애플리케이션을 추가하지 않습니다. 둘째, 납품 후 재정통합시스템 유지보수업체가 감당할 수 있도록 유지보수 범위를 최소화합니다. 셋째, 전문 암호화 제품을 대체하겠다는 주장은 하지 않으며, 방어 범위의 한계를 고객에게 서면으로 고지할 수 있도록 문서화합니다.

## 3. 확정된 요구

대상 데이터는 주민등록번호와 계좌번호 같은 식별번호, 그리고 비밀번호입니다. 식별번호는 양방향 암호화로 저장하고 평문 복원과 마스킹 출력을 제공하며, 비밀번호는 복원이 불가능한 일방향 해시로 저장합니다.

암호화된 컬럼으로 검색하는 화면이나 배치는 없다고 확인되었습니다. 따라서 검색용 색인 컬럼과 결정적 암호화는 두지 않으며, 같은 평문이 매번 다른 암호문이 되는 방식을 쓸 수 있습니다.

응용 프로그램은 SQL이나 PL/SQL 안에서 함수를 호출하는 방식으로 암복호화를 사용합니다. 자바 연동 라이브러리는 간이판에 포함하지 않습니다.

방어 범위는 저장된 데이터 파일과 백업이 유출되는 경우로 정합니다. 데이터베이스 관리자에 대한 방어와 업무 계정의 무분별한 조회에 대한 방어는 이번 목표가 아니며, 이 한계는 고객에게 알릴 문장으로 설계서에 남깁니다. 이 항목은 권장 가정을 채택한 것이므로 고객이 더 높은 수준을 요구하면 재협의가 필요합니다.

## 4. 간이판에서 제외하는 것

기존 전체판 기능 중 직무 분리용 계정 네 종류, 접속 증표 기반 세션 문맥, 복호화 자격 대장, 사용량 임계치, 감사 정책과 감사 로그 분석, 키 저장소 유지 상주 프로그램, 개통 판정 절차, 검색용 색인, 자바 연동 라이브러리는 간이판에 넣지 않습니다. 필요해지면 전체판에서 선별하여 추가합니다.

## 5. 미확정 사항

오라클 버전과 에디션, 운영체제(윈도우 또는 리눅스), 데이터베이스 서버의 운영체제 파일에 키 파일을 둘 수 있는지 여부는 아직 확정되지 않았습니다. 키 보관 방식이 이 세 가지에 좌우되므로 다음 단계에서 결정합니다.
