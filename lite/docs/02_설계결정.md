# 간이판 설계 결정 기록

## 1. 키 보관 방식

키는 데이터베이스 테이블에 저장하기로 결정하였습니다. 이 방식은 상주 프로그램, 서버 파일, 별도 저장소가 모두 필요 없고, 재기동 뒤에도 사람 손 없이 동작하며, 유지보수업체가 관리할 대상이 가장 적다는 장점이 있습니다. 서버 운영체제는 리눅스(RHEL 등)이나, 이 방식에서는 운영체제 파일을 쓰지 않으므로 설치 절차가 운영체제에 좌우되지 않습니다.

대신 한계를 분명히 해 둡니다. 키와 암호문이 같은 데이터 파일과 백업에 들어 있으므로, 데이터 파일이나 백업을 통째로 입수한 공격자는 키를 꺼낼 수 있습니다. 따라서 이 방식은 요구확정서에서 잡은 "데이터 파일과 백업 유출 방어"를 온전히 충족하지 못합니다. 이 방식이 실질적으로 막는 것은 암호화된 컬럼이 SQL로 복사되어 다른 곳으로 나가는 경우입니다. 개발·시험 데이터베이스로의 복제, 암호문 그대로 조회한 결과의 파일 반출이 이에 해당합니다. 응용이 복호화한 뒤 화면, 파일, 로그에 출력한 내용은 보호하지 않습니다. 이 판단은 일반적인 암호 키 관리 원칙에 근거하며 정확도는 높음입니다.

한계를 줄이기 위해 두 가지를 둡니다. 키 테이블에는 업무 계정이 접근하지 못하게 하고 암복호화 함수만 실행하도록 권한을 제한합니다. 그리고 테이블에 저장되는 키는 평문이 아니라 패키지 소스에 감춘 값으로 한 번 감싸 둡니다. 감싼 값은 `wrap` 유틸리티로 소스를 난독화하는 정도의 방어이므로 강한 방어가 아니며, 숙련된 공격자에게는 무력합니다. 정확도는 높음입니다.

## 2. 고객 고지 문장 초안

본 간이 암호화 모듈은 암호화 키를 데이터베이스 내부에 보관합니다. 따라서 데이터 파일이나 백업 전체가 외부로 유출되는 경우에는 암호화가 데이터를 보호하지 못할 수 있으며, 데이터베이스 관리자의 접근에 대한 방어도 제공하지 않습니다. 이 모듈은 암호화된 컬럼이 복호화되지 않은 채 SQL 조회와 복제를 통해 반출되는 경우 평문 노출을 줄이는 수준의 보호를 제공합니다. 응용 프로그램이 복호화한 뒤 화면, 파일, 로그에 출력한 내용은 보호하지 않습니다. 더 높은 수준이 필요한 경우 별도의 키 관리 체계를 도입해야 합니다.

## 3. 나중에 올릴 수 있도록 남기는 여지

키를 읽는 동작은 패키지 안의 함수 하나로 격리합니다. 이후 키를 서버 파일이나 외부 키 관리 시스템으로 옮기려면 이 함수 하나만 바꾸면 되도록 하며, 암호문 형식에 키 번호를 넣어 두어 키 교체 때 이전 암호문을 구분할 수 있게 합니다.

## 4. 선결 확인 사항

`DBMS_CRYPTO` 패키지의 실행 권한은 `SYS`가 부여해야 합니다. 운영 데이터베이스에서 이 권한을 받을 수 있는지는 확인되지 않았습니다. 오라클 버전과 에디션도 아직 모릅니다. 기존 `sql/01_schema/001_precheck.sql`이 이 점검을 하고 있으므로 간이판에서도 재사용을 검토합니다.

## 5. 외부 검토 의견과 처리

2026-10-20에 외부 검토 의견을 받아 코드와 대조한 뒤 처리하였습니다. 전환 검증 SQL이 전환 누락 행을 놓치는 결함은 사실이어서 `rrn_enc IS NULL` 조건을 추가하고 전환 중 입력 중지 절차를 적었습니다. 설치 스크립트가 오류 뒤에도 계속 실행될 수 있다는 지적은, 문자집합 점검이 끝에서 오류 시 중단 설정을 되돌리고 있었으므로 사실이어서 되돌리지 않도록 고쳤습니다. 이에 더해 패키지의 컴파일 오류가 SQL 오류가 아닌 경고로만 나오는 점을 보완하기 위해 설치 스크립트 끝에서 컴파일 오류를 직접 확인하도록 했고, 자체 시험은 하나라도 실패하면 오류로 끝나게 했습니다. 비밀번호 확인이 저장값의 반복 횟수 상한을 검사하지 않아 조작된 저장값이 장시간 계산을 일으킬 수 있다는 지적도 사실이어서 상한 2000000을 두었습니다. 다만 이는 저장값을 쓸 수 있는 사람이 있어야 성립하므로 위험도는 낮습니다. 반복 횟수의 기본값 10000은 권고보다 낮은 것이 맞습니다. 그러나 운영 장비의 측정 없이 올리면 로그인 부하가 커질 수 있어 값은 바꾸지 않고, 측정과 결정을 인계 점검표의 항목으로 만들었습니다. 화면과 로그 노출에 대한 서술은 응용이 복호화한 값에는 해당하지 않으므로 보호 범위를 좁혀 고쳤습니다. 실제 오라클에서의 설치, 재기동, 키 교체, 복구 확인은 코드로 해결할 수 없는 일이어서 인계 점검표의 확인 항목으로 만들었습니다.
