# 운영 환경 설치 후 확인 절차

## 1. 원칙

운영 환경에서는 데이터베이스의 상태를 되돌릴 수 없게 바꾸는 시험을 하지 않습니다. 이 꾸러미의 `checks/` 폴더에는 그런 것을 뺀 다섯 개만 담았습니다. 키를 교체하는 시험(`T4`)은 담지 않았습니다. 키 교체는 `SFC_KEY`에 키를 영구히 하나 더하므로, 실제로 키를 바꿔야 할 때만 안내서 제6장의 절차로 하십시오. 모든 것을 지우는 `sql/90_uninstall.sql`도 운영에서는 실행하지 마십시오. 실행하면 키가 사라져 암호화한 자료를 영원히 읽을 수 없게 됩니다. 아직 암호화한 자료가 하나도 없고 설치를 처음부터 다시 해야 하는 경우만 예외입니다.

## 2. 시작 전에 확인할 것

| 확인 | 내용 |
|---|---|
| `DBMS_CRYPTO` 권한 | `SYS`가 `SFC_OWNER`에 `DBMS_CRYPTO` 실행 권한을 주어야 합니다. 운영 정책으로 승인받았는지 먼저 확인하십시오. 승인되지 않으면 설치할 수 없습니다. |
| 꾸러미 무결성 | 압축을 풀기 전에 `.sha256` 파일로 압축 파일의 해시를 확인하고, 푼 뒤 최상위 폴더에서 `sha256sum -c MANIFEST.sha256`을 실행해 모두 `OK`인지 봅니다. |
| 클라이언트 문자집합 | SQL 파일은 CP949입니다. SQL*Plus 창에서 `NLS_LANG=KOREAN_KOREA.KO16MSWIN949`를 먼저 맞춥니다. 안내서 제3장에 있습니다. |
| 대상 PDB와 테이블스페이스 | `10_sys_setup.sql`에 넘길 테이블스페이스 이름을 정하고, 설치 스크립트를 실행할 PDB로 접속하는지 확인합니다. |
| 백업 | 설치 직후 데이터베이스 전체 백업을 받을 수 있는지 확인합니다. 봉인값과 키를 잃으면 자료를 복구할 방법이 없습니다. |
| 작업 시간 | 재기동 확인(아래 3번 항목)을 하려면 점검 시간이 필요합니다. 운영 정책이 허락하지 않으면 그 항목은 건너뛰고 기록에 남깁니다. |

## 3. 설치와 확인의 순서

먼저 안내서 제3장의 설치 1~6단계를 순서대로 실행합니다. 6단계 자체 시험은 어떤 표에도 쓰지 않으므로 운영에서 실행해도 안전합니다. 마지막 줄이 `OCS-LITE SELFTEST OK`여야 합니다. 이어서 `checks/` 폴더의 스크립트를 아래 순서로 실행합니다. 이 폴더로 이동한 뒤 SQL*Plus를 실행하십시오.

| 순서 | 확인 | 접속 | 실행 | 기대 결과 |
|---|---|---|---|---|
| 1 | 업무 스키마의 함수 호출과 접근 차단 | 실제 업무 스키마 | `@T2_app_calls.sql` | `--- pass 11, fail 0` 와 `T2 OK` |
| 2 | 전환 검증 질의 | `SFC_OWNER` | `@T1_decode_check.sql` | `PASS T1 …` 와 `rows counted by the manual query : 3 (ids 2,3,4)` |
| 3 | 재기동 전 자료 남기기 | `SFC_OWNER` | `@T3_prepare.sql` | 두 행이 표시됨 |
| 4 | 재기동 뒤 복호화 | `SFC_OWNER` | 데이터베이스를 재기동한 뒤 새 창에서 `@T5_verify_after.sql` | `T5 OK (2 rows)` |
| 5 | 정리 | `SFC_OWNER` | `@T6_cleanup.sql` | `T6 done` |

1번은 `SELECT ANY TABLE`이나 `EXECUTE ANY PROCEDURE` 권한(예: `DBA` 롤)을 가진 스키마에서 실행하면 이유를 밝히고 `ORA-20991`로 멈춥니다. 소유 계정에서도 같습니다. 접근 차단을 보는 시험이기 때문입니다. 마땅한 업무 스키마가 없으면 권한이 없는 시험용 스키마를 만들어 `sql/40_connect_app.sql`로 연결한 뒤 실행하십시오. 2번과 3번은 `SFC_OWNER` 계정에 표를 만들었다가(2번은 곧바로 지웁니다) 3번의 표는 5번에서 지웁니다. 소유 계정을 이미 잠갔다면 `SYS`에서 `ALTER USER SFC_OWNER ACCOUNT UNLOCK;`으로 풀었다가 확인을 마친 뒤 다시 잠그십시오.

비밀번호 해시의 반복 횟수는 운영 장비에서 재어 정해야 합니다(안내서 제4.2절). 소유 계정에서 다음을 실행해 소요 시간을 기록하십시오. 시험 인스턴스에서는 10000회에 0.48초, 100000회에 5.10초였고 횟수에 비례했습니다. 큰 값은 한 세션의 CPU를 그만큼 쓰므로 업무가 적은 시간에 하십시오.

```sql
SET TIMING ON
SELECT PKG_SFC.pwd_hash_hex('measure', NULL, 10000)  FROM DUAL;
SELECT PKG_SFC.pwd_hash_hex('measure', NULL, 100000) FROM DUAL;
```

## 4. 확인이 끝난 뒤

소유 계정을 잠그고(`ALTER USER SFC_OWNER ACCOUNT LOCK;`), 데이터베이스 전체를 백업하고, 안내서 제11장 인계 점검표에 결과를 기록합니다. 설치한 꾸러미의 `VERSION` 파일에 적힌 소스 판 번호도 함께 남기십시오. 이후 문제가 생겼을 때 어느 판인지 알 수 있어야 합니다.

## 5. 아직 어디서도 확인하지 못한 것

다음 항목은 시험 인스턴스에서도 확인하지 못했으므로 운영에서 처음 겪게 될 수 있습니다. 미리 알고 있어야 하는 것들입니다.

| 항목 | 알아 둘 것 |
|---|---|
| 키 교체 | 시험하지 않았습니다. 필요할 때까지 하지 마십시오. 하게 되면 안내서 제6장을 따르고 실행 전에 백업을 받으십시오. |
| 재컴파일 때의 `ORA-04068` | 재컴파일하면 이미 연결된 세션의 첫 호출이 실패할 수 있다고 안내서 제8장에 적었으나 실제로 확인하지 않았습니다. 재컴파일은 점검 시간에 하고 연결 풀을 재생성하십시오. |
| 백업 복구본에서의 복호화 | 확인하지 않았습니다. 실제 자료를 암호화하기 전에 복구 시험을 한 번 해 두기를 권합니다. |
| 문자집합 점검이 어긋난 창에서 멈추는지 | 맞는 창에서 통과하는 것만 확인했습니다. |
| 반복 횟수의 운영값 | 운영 장비의 측정 뒤 결정합니다. 기본값 10000은 권고 수준보다 낮습니다. |

## 6. 문제가 생기면

화면에 나온 오류 메시지를 줄이지 말고 전부 보관하고, 어느 단계에서 났는지를 기록하십시오. 대부분의 오류는 안내서 제7장의 표에 원인과 조치가 있습니다. 스크립트는 오류가 나면 SQL*Plus를 종료하도록 되어 있으므로 창이 닫혀도 놀라지 말고 그 창의 스크롤 내용을 먼저 확인하십시오. 원인을 모르는 상태에서 `90_uninstall.sql`로 지우고 다시 설치하려 하지 마십시오. 아직 암호화한 자료가 없다고 확신할 때만 그렇게 하십시오.
