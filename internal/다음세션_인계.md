# 다음 세션 인계 메모 (2026-10-11 작성)

새 세션을 열면 이 파일과 `internal/진행현황.md` 를 먼저 읽고 이어서 한다. 작업 브랜치는
`claude/oracle-encryption-module-design-0xvj2q` 이다. PR 은 사용자가 요청할 때만 만든다.

## 사용자와 일하는 방식

한국어 존댓말로 간결하게 답한다. 한 번에 한 단계씩 안내하고 결과를 기다린다. 복사해 붙일 명령에는 프롬프트 접두사를 붙이지 않는다.
아는 것과 추측을 구분하고, 확인하지 않은 것은 확인 전이라고 밝힌다. 마스터 키, 증표용 키, 계정 암호, 실제 주민등록번호는 대화에 쓰지 않는다(모양과 판정만 보고받는다).
`902_selftest.sql` 과 `990_drop_all.sql` 은 운영 시스템에서 실행하지 않는다. 매뉴얼(설치, 개발자)은 해라체로 쓰고 개발·시험 과정의 이력 서술은 넣지 않는다.
사용자는 프로젝트 기간과 절차의 양을 걱정한다. 문서나 검증을 더 확장하지 말고, 개발자가 대기 중이므로 개발 환경을 먼저 갖추는 일을 우선한다.

## 현재 상태

시험 PC(윈도우, `C:\ocsecure`, 오라클 19c PDB `ORCLPDB`)에 개발·시험 편 설치가 끝나 있다. 키 유지 프로그램은 작업 스케줄러로 돌고, `OCS_OWNER` 는 잠겨 있으며, 업무 계정 `sfis` 와 개발용 계정(사용자가 직접 만든 이름)이 `480` 으로 연결되어 있다.
개발 모드(`APPCTX_MODE=SIMPLE`)는 현재 **켜져 있다**(개발용 계정을 만들 때 `910` 을 실행). 끄려면 `SYS` 로 `911`.
개발자 키트: `dist/ocsecure-dev-kit-20261008.zip` (자바 연동 라이브러리, 개발자 매뉴얼, 예제 `MemberExample`·`OcsWork`, 예시 스크립트, 시작 안내). 코드나 매뉴얼을 고칠 때마다 `python tools/make_dev_kit.py` 로 다시 만들고 커밋한다.
개발자 매뉴얼(`docs/개발자/개발자_매뉴얼.md`)은 작업 순서 구조로 다시 썼고 예제는 실제 환경에서 확인했다(`MemberExample`, `OcsRecipeCheck` 15/0, `--limit` 14/0).

## 바로 이어서 할 일

1. 개발 모드가 증표가 붙은 `login` 을 받는지 확인한다. 시험 PC 명령 프롬프트에서 `MemberExample` 을 실행하되 증표 키 자리에 임시 값(0 을 64개)을 입력한다. 같은 일곱 줄이 나오면 된다.
2. 1이 되면 개발자 매뉴얼 제6.5절과 제6.2절, 키트의 시작 안내를 고친다. 모든 환경에서 같은 코드로 `new OcsSessionSupport(new OcsAppProof(키))` 를 쓰고 키는 환경 변수 `OCS_APPCTX_KEY` 에서 읽는다. 키가 없으면 기동 단계에서 예외를 낸다. 코드에서 `new OcsSessionSupport(null)` 과 키 유무 분기를 없앤다. 개발 설정에는 임시 값, 운영에는 실제 키를 넣는다.
3. 개발자 PC 접속(3단계)을 안내한다: 시험 PC 에서 `ipconfig`, `lsnrctl status`, IP 주소로 `sqlplus` 접속, 방화벽 1521 허용(개발자 대역만), 개발자 PC 에서 `Test-NetConnection <IP> -Port 1521`, SQL 도구에서 `login` 한 줄 시험.
4. 보안 정리: `SFIS` 의 주민등록번호 복호화 자격 회수와 감사 기록(`RATE_EXCEEDED`, `REVEAL_GRANT`, `REVEAL_REVOKE`) 조회 결과를 사용자에게서 아직 받지 못했다. `OCS_AUDITOR` 로 `V_SEC_EFFECTIVE_REVEAL` 에 `SFIS` 행이 없는지 확인한다.

## 아직 하지 않은 것

지금까지의 변경을 `main` 으로 합치기와 설치 패키지(`dist/ocsecure-install-*.zip`) 재생성. 시험 PC 의 패키지는 옛 판이며 `810` 의 표시 덮어쓰기 결함(수정됨)과 새 예제 파일이 들어 있지 않다.
유지보수 매뉴얼과 설치 매뉴얼의 용어(문맥 → 세션 등록) 통일, 유지보수 매뉴얼의 해라체 통일. 개발자 매뉴얼만 새 용어와 해라체다.
`OcsWork` 실행, 비밀번호 반복 횟수 점진 상향, 기존 비밀번호 체계 이행, MyBatis 매퍼 XML 자체, 데이터베이스 안 배치의 문맥, 리눅스 편 전체와 운영 편 전체.
설치 단계를 자동화하는 실행 파일은 선택 사항이며 일정을 보고 정한다.
`claude/epic-darwin-x03sde` 브랜치 삭제와 저장소 비공개 전환은 사용자가 정할 일이다.
